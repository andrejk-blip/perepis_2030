# Supabase — финальная настройка перед публикацией v14.9

Ниже порядок, который лучше выполнить **до замены `index.html` на GitHub Pages**. Административный `service_role` в игру не вставляется.

## 1. Сделать резервную точку

В Supabase откройте проект, который используется игрой, и убедитесь, что это рабочая база зачёта `colleagues-2026`. Если в проекте есть важные данные, перед изменением функций сохраните определения RPC из шага 2 в отдельный текстовый файл.

## 2. Диагностика без изменений

Откройте **SQL Editor → New query**, вставьте весь файл `00_SUPABASE_PRECHECK.sql` и нажмите **Run**.

В первом результате должны быть функции `census_leaderboard` и `census_region_leaderboard`. Сохраните этот результат. Особенно посмотрите на их определения:

- если внутри **нет** `auth.uid()`, вероятная причина рейтинга `1/1` — RLS; миграция ниже должна помочь;
- если внутри **есть** явное условие с `auth.uid()`, автоматический патч специально его не тронет. В таком случае после запуска миграции пришлите определение функции — потребуется точечная редакция SQL по фактической таблице результатов.

## 3. Выполнить финальную миграцию

Создайте второй запрос, вставьте `01_SUPABASE_FINAL_MIGRATION.sql` целиком и нажмите **Run**.

Скрипт делает три вещи:

1. переводит существующие RPC общего и регионального рейтинга в `SECURITY DEFINER`, **только если в них нет явного `auth.uid()`**;
2. создаёт закрытую таблицу `census_feedback` и RPC `census_submit_feedback`;
3. создаёт private Storage bucket `census-feedback`, куда игрок может только загрузить изображение в собственную папку.

## 4. Проверить серверную часть

Запустите `02_SUPABASE_VERIFY.sql`. Ожидаемый результат:

- `security_definer = true` у функций рейтинга, либо понятный `ATTENTION`, если в функции есть явный `auth.uid()`;
- `feedback_table = census_feedback`;
- `feedback_rpc = census_submit_feedback(jsonb)`;
- bucket `census-feedback`: `public = false`;
- присутствует политика `census_feedback_upload_own` с командой `INSERT`.

## 5. Проверить общий рейтинг двумя игроками

После публикации откройте игру в двух независимых браузерных профилях. Введите разные имена, сделайте хотя бы по одному действию, меняющему счёт, и откройте **Таблица рекордов → Общий рейтинг**.

Оба браузера должны видеть обе записи. Если каждый видит только себя:

1. снова выполните первый SELECT из `00_SUPABASE_PRECHECK.sql`;
2. найдите `auth.uid()` в определении `census_leaderboard`;
3. пришлите определение функции — по нему можно безопасно переписать запрос без раскрытия внутренних данных.

## 6. Проверить обратную связь

В игре нажмите **«Сообщить»**. Браузер попросит разрешить захват вкладки/экрана — выберите текущую вкладку игры. После этого:

1. снимок должен уже находиться в форме;
2. обведите место ошибки;
3. напишите тестовый комментарий;
4. отправьте.

Проверка для разработчика:

- **Table Editor → census_feedback** — должна появиться строка;
- **Storage → census-feedback** — должен появиться JPG в папке UUID пользователя.

Сейчас это и есть административный интерфейс для тестирования. Отдельную игровую админку лучше делать позже, когда накопятся реальные обращения.

## 7. Что нельзя делать

- Не вставлять в `index.html` `service_role`, secret key, пароль от БД или токен владельца проекта.
- Не делать bucket `census-feedback` публичным.
- Не выдавать `SELECT` на `census_feedback` ролям `anon` или `authenticated`.
- Не отключать RLS на таблицах с пользовательскими данными ради починки рейтинга.

## 8. Если обратная связь не отправляется

- `404` — обычно не создан RPC/таблица: повторите шаг 3.
- `401/403` — проверьте, включён ли Anonymous Sign-In в Supabase Auth и выдано ли `authenticated` право execute на RPC.
- скриншот не загружается, а текст отправляется — проверьте bucket и storage policy из шага 4.
- браузер не даёт скриншот — это может быть отказ пользователя/политика браузера; скрытый захват без разрешения браузеры не позволяют.
